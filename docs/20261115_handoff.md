# 인수인계와 작업 지시: pairl (2026-11-15 기준)

**pairl** = Passive Adaptive Impedance Reinforcement Learning. 적응하는 하위 층을 안에 가진 RL 정책으로, 제약 만족과 passivity는 학습과 무관하게 구조로 성립한다.

이 문서는 cloud 환경에서 진행한 연구를 사용자의 Linux PC(RTX 5080)에서 Claude Code가 이어받기 위한 문서다. 사실과 수치는 모두 번들 안의 기록과 사양(spec)에서 옮겼다. 기록과 이 문서가 다르면 기록이 옳다. 이 문서와 `CLAUDE.md`가 번들 안의 같은 이름 파일을 대체한다.

### 1.5 코드 정리 규칙

- **수치를 바꾸지 않는다.** 바꾸는 것은 import 문, 경로, 파일 위치뿐이다. 함수 이름, 기본값, 계산 순서, `jax_enable_x64`(모든 진입점의 첫 줄)는 그대로 둔다. 판정 기준은 1.8의 port check가 EXACT로 나오는 것이다.
- **Import.** 평평한 import(`import l1, l2, env, controller as C, params as P, model as Mo`)를 package import로 바꾼다(예: `from pairl.stageb import params as P`). 모듈 이름은 유지한다.
  - 모듈 수준 상태(`env.COST_V`, `l2.ACT_MODE`, `l2.set_mode`)는 모듈 속성으로 남아야 한다. 같은 모듈 객체를 쓰게 import하고, `from ... import COST_V`처럼 값을 복사하지 않는다.
  - `sys.path.insert(0, '.')` 같은 경로 조작은 지운다.
- **경로.** `'../../records'`, `'../records'`, `'../../figures'` 같은 상대 경로(현재 132곳)를 모두 `pairl.paths`의 상수로 바꾼다.
  - 어떤 script도 현재 디렉터리에 의존하지 않게 하고, 실행은 repo 루트에서 `python script/...`, `python eval/...`로 한다.
  - `paths.py`는 `PAIRL_ROOT` 환경 변수가 있으면 그것을, 없으면 package 위치로 루트를 정한다.
- **명령행 인자는 그대로 둔다.** run 디렉터리를 인자로 받는 script는 경로를 받으므로, 새 위치를 넘기면 된다(예: `python script/l2_train.py data/runs/<timestamp>/l2_attempt4 ...`, `python eval/diagnostics/l2_signal_check.py records/l2_signal_check.json data/runs/20261115134229/l2_attempt3:300 n=512 start=2 cost=4`).
  - 진단 JSON의 key는 run 디렉터리의 basename(예: `l2_attempt3:300`)이라 바뀌지 않는다.
- **임시 파일**은 `paths.TMP`(`_local/tmp/`, git 제외)에 쓴다(`verify_env.py`와 `f32_run.py`의 float64 기준 파일, 병렬 launcher의 compilation cache). 1.9 참고.
- `l2_signal_check.py`, `l2_restart_behavior.py` 등은 기록 JSON을 읽고 고쳐 쓴다. 같은 파일을 쓰는 프로세스를 동시에 돌리지 않는다.

### 1.6 기록과 문서

- **번들에서 온 사전 등록 파일은 고치지 않는다**(`records/*_plan.md`; 고치면 `*.hash`의 hash 사슬이 깨진다). 새 사전 등록에는 개정과 결과를 끝에 덧붙이기만 하고, 그때마다 hash 줄을 더한다. 그 안의 명령은 번들 구조 기준이다(`code/stageb`에서 실행, run은 `../../records/<run>`). `records/README.md`에 1.4의 대응과 이 사실을 적는다.
- **노트 빌드:** `script/build_docs.sh <name>`이 `docs/notes/<name>.tex`를 `build/`(git 제외)에서 XeLaTeX 3-pass로 렌더하고, PDF를 `docs/notes/<name>.pdf`로 복사한다.
  - fontspec + Noto Serif CJK KR로 렌더하고, 원본 tex는 `kotex`를 유지한다(번들의 `build_tex.sh` 방식 그대로).
  - 게이트 errors, undefined, multiply-defined, overfull, missing-char가 모두 0이어야 한다.
  - `docs/notes`와 `docs/figures`가 형제 디렉터리라 `\graphicspath{{../figures/}}`는 그대로 맞는다. 바꿀 필요가 있으면 확인하고 고친다.
- **spec 안의 경로 표기**(`\texttt{records/...}`, `\texttt{code/stageb/...}` 등 약 26곳)를 새 위치로 고친다.
  - 사전 등록 파일을 가리키는 `records/...`는 그대로 맞으므로, run 디렉터리와 코드 경로만 바뀐다.
  - 고친 뒤 `script/check_sync.py`가 0이 되게 한다. 이 script는 spec이 인용한 수치와 이 문서(`docs/20261115_handoff.md`)의 핵심 수치(§6, §7)를 기록에서 다시 계산해 문자열로 대조한다.
  - 경로를 담은 대조 문자열이나 수치 문자열을 바꾸면, `check_sync.py`의 해당 블록도 같은 변경으로 맞춘다.
- `records/verified_values.md`의 `## Divergence (open)`는 비어 있어야 한다.

### 1.11 평가와 보고 형식 (상시 규칙, 2026-11-16)

  - P1 잡기: 단계 1 끝에 붙어 있음. P2 옮기기: 단계 2의 마지막 0.5 s 내내 붙어 있고 손끝이 p*에서 2 cm 안. P3 누르기: 단계 3의 마지막 1 s 내내 붙어 있고 윗면을 누르며 평균 힘이 f*의 ±10% 안. P3' 등급: 그 1 s의 평균 힘이 다른 등급보다 맞는 등급의 목표에 가깝다(닿은 episode만, 수를 보고). P4 놓기: 단계 4의 마지막 0.5 s 내내 놓여 있고 손끝이 p*에서 2 cm 안.
  - 단독(각 단계의 시작 상태에서; 단계 4는 평가 전용 시작 상태 `env.restart` kind 4)과 처음 시작에서의 사슬(P1, P1&P2, P1&P2&P3, 전부)로 보고하고, 늦은 잡기를 참고로 둔다. 모든 비율에 bootstrap 95% 구간.
- 모든 보고의 순서: (1) 성공표(행 P1, P2, P3, P3', P4 단독과 전체 사슬; 열 L1 기준 뇌, attempt 3의 300, 이전 최선, 현재; 구간이 0을 배제하는 변화 표시), (2) 보장 한 줄(관절 위반, 비유한 상태, 최소 tank margin), (3) 지금의 병목과 그 이유, (4) 그 다음에만 비용, KL, clip, sigma, 손 잔차 등.
- group 폴더 맨 위에 `success_table.md`, `success_curve.png`, `funnel.png`, 대표·비교·격자 영상(MP4와 GIF 미리보기), 성공표로 시작하는 `summary.md`를 둔다. `INDEX.md`의 group 줄에 전체 사슬 성공률과 P1을 적는다. `script/finish_run.sh`가 arm 끝과 100 반복 평가마다 만든다.
- 추가 평가 작업은 CPU에서 낮은 우선순위로 돌리고(`safe_run.sh`, 병렬 launcher), GPU는 arm 사이에만 쓴다.

### 1.10 data/runs의 구성 (상시 규칙, 2026-11-16)

- 한 plan과 한 코드 상태로 만든 run(예: pilot O의 모든 arm)은 한 group 폴더 `data/runs/<YYYYMMDDHHMMSS>/<run_name>/`에 둔다. timestamp는 group을 띄운 시각이다. run 이름은 지금 형태를 유지하므로 진단 JSON의 key(run basename)는 그대로 맞는다. 이름으로 찾을 때는 `pairl.paths.run_dir(name)`을 쓴다.
- group마다 `manifest.json`(plan과 그 hash, git commit과 작업 트리가 더러우면 diff hash, 정확한 명령, platform, 시작과 끝 시각, 상태(complete / stopped early / failed), 목적 한 줄)을 두고, `data/runs/INDEX.md`에 group마다 한 줄(timestamp, 목적, plan, 상태, 핵심 결과)을 둔다. group을 만들거나 끝낼 때 둘 다 갱신한다.
- `script/l2_train.py`가 `group=new`(또는 `group=<timestamp>`)로 group 폴더와 manifest를 직접 만든다.
- smoke test, 시간 측정, debugging run은 `data/runs`에 두지 않는다(`_local/tmp`에서 돌리고 지운다). 일찍 멈추거나 실패해서 보고된 결과가 없는 run은 지운다. 단, plan, spec, records, check_sync가 인용하면 남긴다.
- 기존 run의 group(7개)은 `data/runs/INDEX.md`, 옮긴 대응은 `records/runs_grouping_map.tsv`에 있다. 원본은 번들 zip의 `records/<run>/`에 있다.
- **시각 요약 (상시 규칙).** group 폴더의 맨 위에 한눈에 볼 그림을 둔다.
  - `summary.png`: group 안 모든 run의 학습 곡선(훈련 비용, 시작별 내장 평가 비용, KL, clip 몫, goal과 강성의 표준편차, 손 전이 잔차, 최소 tank margin).
  - `eval_<run>_it<NNNN>.png`: 각 run의 마지막 checkpoint의 판정 평가(시작별 비용, 결정론과 fully sampled, 잡기, 정확히 누른 몫, 유지 오차).
  - pilot은 `decision.png`: arm마다 arm − C의 짝지은 차이와 bootstrap 95% 구간, 채택 기준선.
  - `<run>_start{0,2,3}_it<NNNN>.gif`: 각 run의 마지막 checkpoint(긴 run은 주요 checkpoint도)의 rollout. git 제외, 한 개 약 5 MB 이하(frame stride).
  - `summary.md`: 목적, plan, 상태, 핵심 수치, 위 그림의 link. `INDEX.md`가 각 `summary.md`를 link한다.
  - run이 끝나면 `sh script/finish_run.sh <run>`이 자동으로 만든다(판정 평가는 학습과 같은 GPU에서 arm 사이에, GIF는 CPU에서 낮은 우선순위로). 과거 group은 기록에서 다시 만들고, 새로 만든 GIF의 platform을 `gifs.md`와 `summary.md`에 적는다.

## 3. 연구 목표와 바꾸면 안 되는 것

**목표.** 적응 제어의 철학을 구조에 담은 RL framework를 만든다.
- 정책 = 뇌(학습된 NN, task 수준의 의도) + 손(가상 impedance와, 정지 상태에서 측정된 mismatch로 갱신되는 적응 기억).
- 보장(제약 만족, passivity)은 학습과 무관하게 구조로 성립한다.
- 핵심 기여는 두 층이 서로의 역할을 알고 정보를 주고받는 결합이다. 뇌→손으로는 goal과 강성이, 손→뇌로는 에너지 장부가 간다.
- 사용자가 지금 가장 중요하게 보는 연구 질문은 **"구조 안에서 각 parameter가 의도한 역할대로 학습되게 하는 학습 체계(reward, update 설계)"**다.
- 최종적으로 7-DOF로 간다.

**불변 조건 (사용자 승인 없이 바꾸지 않는다).**
- 보장은 학습되지 않는 요소(energy tank와 gate, 제약층, direction-preserving saturation, 접촉 guard)에서 나온다. 학습이 최적이어야 보장이 서는 방식은 받아들이지 않는다.
- NN의 비선형성과 universal approximation을 유지한다.
- class 수준의 구조만 쓴다. NN 안에 instance 모형(예: 중력 항)을 넣지 않는다. 공칭 기구학(공칭 링크 길이의 Jacobian)과 torque sensing은 class 수준으로 허용되어 쓰고 있다.
- State feedback만 다룬다.
- 단순한 적층(RL이 reference를 만들고 적응 제어가 추종)은 기여로 보지 않는다.

## 5. 현재 시스템 (spec 개정 16)

**Plant와 제약.**
- 평면 3관절 팔, gripper, 물체, block.
- 관절 상자 $c=(0.9,-1.3,-0.5)$, $h=(0.9,1.1,1.2)$ rad. 입력 상자 $\bar u=(120,60,25)$ N·m.
- 제어 주기 2 ms(RK4 네 번), 뇌의 결정 주기 50 ms(제어 25 step), episode 최대 11 s(결정 220개).

**과제의 네 단계.** 각 단계의 길이는 episode마다 무작위다(1.5–2.5, 2–3, 2–3, 1.5–2.5 s).
1. 물체로 가서 잡기.
2. $p^\star$로 옮기기.
3. block 윗면을 $f^\star$로 누르기.
4. 놓고 $p^\star$로 물러나기.

- 잡기 조건: gripper 닫힘 명령, 손끝이 잡는 점에서 2 cm 안, 관절 속도 최대값 0.1 rad/s 이하.
- 목표 힘은 질량 등급(무거움: 물체 질량 > 0.85 kg)에 따라 $f_{\mathrm{light}}$ 또는 $f_{\mathrm{heavy}}$다. 뇌는 두 후보를 관측하지만 등급은 관측하지 않으므로, 장부의 하중으로 판단해야 한다.

**비용** (개정 15, `env.cost_rate`, `env.COST_V = 4`). 보상은 결정 구간 비용률 적분의 음수다. 거리는 0.1 m 단위다.
- 단계 1: 손끝–잡는 점 거리.
- 단계 2: 들었으면 $\|p-p^\star\|$, 아니면 $1+\|p-o\|+\|o-p^\star\|$.
- 단계 3: 들었으면 누르기 항 $+|p_x-p^\star_x|$, 아니면 $1+\|p-o\|+(1+\text{물체–윗면 중심 거리}+|o_x-p^\star_x|)$.
  - 누르기 항은 윗면 힘이 있으면 $\min\{((f-f^\star)/f^\star)^2,1\}$, 없으면 $1+\|p-p_c\|$.
- 단계 4: $\|p-p^\star\|+\xi$.
- 모든 단계에 과힘 penalty $5\max(f-2f^\star,0)/f^\star$를 더한다.

**뇌.**
- Actor MLP 31–128–128–13(tanh). 출력은 평균 6, 표준편차 6(상태 의존; 범위 goal [0.005, 0.3], 강성 [0.05, 0.5]), gripper logit 1.
- Critic MLP 37–128–128–1. 관측 31에 privileged 6(단계의 남은 시간, 물체 질량, $f^\star$, $p^\star$와 윗면의 높이 차, 등급, 예산)을 더한다.
- 관측(31): 관절 자세(정규화) 3, 속도 3, 측정 외력 torque 3, 단계 one-hot 4, 잡는 점 2, $p^\star$ 2, $(f_{\mathrm{light}},f_{\mathrm{heavy}})$ 2, 손끝 2, 잡음 $\xi$ 1, tank 수준 1, 장부 $\bar\lambda$ 1, 장부 하중 $u_{\mathrm{load}}$ 3, 상대 위치 $o-p$ 2, $p^\star-p$ 2.
- 행동(개정 16, `l2.goal_of`, 모드 `task`):
  - $q_d=\Pi_{\mathcal C_q}(q+J_{\mathrm{nom}}^+\Delta p+n\,v_N)$, $\Delta p=0.3\tanh(u_{1:2})$ m, $n=0.3\tanh(u_3)$ rad. $J_{\mathrm{nom}}^+$은 감쇠(0.02) pseudo-inverse, $v_N$은 kernel 방향이다.
  - 강성 $K=K_{lo}(K_{hi}/K_{lo})^{\mathrm{sigmoid}(u_{4:6})}$, $K_{lo}=(50,25,10)$, $K_{hi}=(400,200,80)$.
  - Gripper는 Bernoulli다.
  - 탐색 잡음은 10 결정(0.5 s) 동안 유지한다.
  - 평가는 결정론적이다(평균 행동, logit > 0).

**손.**
- $u_{\mathrm{ad}}=G_W(q)^\top(\bar a+z)$.
- $G_W$: MLP $(\sin q,\cos q)$ 6–64–64–21 → tanh → 7×3. Prior $\bar a=50\tanh(\cdot)\in\mathbb R^7$.
- 기억 $z\in\mathbb R^7$은 정지 지시자 $\zeta$(관절 속도 ≤ 0.3 rad/s가 0.1 s 이상)가 켜진 동안에만 갱신된다.
  $$\dot z=-\lambda_s G(G^\top G+\epsilon I)^{-1}\hat m,\qquad \hat m=u_{\mathrm{ad}}-\tau_{\mathrm{prev}}-\hat\tau_{\mathrm{ext}},\qquad \lambda_s=5,\ |z|\le 50$$

**Role loss (손의 학습).**
- 기록된 rollout을 replay해 $\mathrm{mean}\,w(t)\|u_{\mathrm{ad}}-u^\star\|^2$를 줄인다. $u^\star=g(q)-d$는 privileged 신호다.
- $w=1-e^{-\lambda_s r(t)}$. $r(t)$는 마지막 짐 변화(잡기, 놓기, 물체를 든 채 시작한 episode의 시작) 이후의 정지 누적 시간이다.
- 반복마다 Adam 16 step × 32 episode, lr $10^{-3}$, gradient clip 1.0.

**PPO.**
- $\gamma=0.99$(결정 단위), GAE $\lambda=0.95$, clip 0.2, value 계수 0.5, entropy 계수 $10^{-3}$.
- Adam lr $3\cdot10^{-4}$, gradient norm clip 0.5, 5 epoch, minibatch 4096 결정, batch마다 advantage 정규화.
- 반복당 128 episode(6144개 pool에서): 원래 시작 64, 단계 2 시작 32, 단계 3 시작 32(`restart=0.5`).
- L2의 모든 run이 이 hyperparameter를 썼고, 학습률을 바꾼 적이 없다.

**등록 기준** (반복 300, spec `sec:l2a3`):
- (G) 충족: 반복 1–300 모두 관절 위반 0, 비유한 상태 0, 최소 tank-bound margin $2.6\cdot10^{-4}$ J.
- (H1) 불충족: 평가 260–300의 손 전이 잔차 평균 3.196 N·m(기준 1.768).
- (H2) 불충족: 기준 뇌 + 학습된 손의 등급 결정 0.922(기준 0.95).
- 중단 규칙은 적용되지 않았다: 처음 시작에서 든 채 힘 구간에 윗면을 누른 몫 0.688.

**뇌.**
- 단계 3 시작에서 정확히 누른 몫 0.641, 단계 2 시작의 유지 오차 0.0278 m.
- 처음 시작의 평가 비용 17.37(L1 기준 뇌 2.290).
- 잡기가 비용을 지배한다: 잡지 못한 19개(64개 중)의 평균 비용 37.460(spec `sec:l2status`).
- 누르는 힘은 등급과 무관하다(두 목표의 가중 평균).
- 결정론적 평가는 놓기를 과소평가한다: 단계 4에 든 45개 중 0.089만 놓지만 표본 gripper로는 1.000.

**손.**
- prior는 학습됐다.
- 자세 사이의 옮김(전이 잔차)은 반복 30 무렵 0.44에서 300에 4.43(중앙값)으로 표류했다.
- 접촉 step을 빼도 표류했다(새 data 오프라인 실험, `records/l2_hand_fresh_b140.json`, `records/l2_hand_fresh_b300.json`).
- 해석(가설, spec `sec:l2a3`): role loss는 정지할 때마다 재보정되는 rollout 안의 오차만 재므로, 옮김을 정하지 못한다.

**장부 → 뇌.** 장부에는 등급 정보가 있지만(L1 규칙으로 0.911), 학습된 뇌는 그것을 쓰지 않는다(등급 결정 0.45–0.48).

**최적화.** KL 중앙값 0.0555, clip 몫 0.40, goal 표준편차 0.211 → 0.0507, 훈련 비용 기울기 $-0.024$/반복(251–300). 수렴하지 않았다.

## 7. 계산 환경과 GPU 이식

**지금까지.**
- cloud container, CPU 2 core(Xeon 2.1 GHz), RAM 7 GB, GPU 없음.
- 반복당 30 s(rollout 15.5 s). 세 번째 시도의 반복 101–300은 1.66 h(평가 포함 1.94 h).
- 모든 코드는 float64(`jax_enable_x64`)다.

**이식 점검** (1.8 뒤, 학습 없음).
1. `JAX_PLATFORMS=cpu python script/port_check.py`: cloud 기록 대비 비교다(cloud에서는 episode별 상대 차이 0, 평균 비용 17.370263, 6.421145, 4.681267; `records/port_check_cloud.log`).
   - 이 PC(Core Ultra 9 285K)에서는 같은 코드로 17.373252, 6.421073, 4.681267이 나와 DIFFERENT로 판정된다. 기계어에 따른 반올림 차이가 잡기·접촉의 이산 사건에서 커진 것이다(`records/verified_values.md`의 `## Platform reproduction`).
   - 이 PC의 재현 판정은 `JAX_PLATFORMS=cpu python script/port_check.py ref=pc`로 하고, `records/port_check_pc_baseline.json`과 192개 episode 비용이 모두 bit 단위로 같아야 EXACT다.
   - cloud 기록은 유효하며 재계산으로 덮어쓰지 않는다. 앞으로의 run과 진단은 이 PC에서 만들고, 비교는 한 platform 안에서만 한다.
2. GPU에서 `python script/port_check.py bench=1 sizes=64,256,1024,4096`.
   - GPU의 float64 결과는 연산 순서 때문에 CPU와 다를 수 있다. 정확한 일치는 요구하지 않는다. `ref=pc`를 붙여 이 PC의 CPU 기준과 비교하고, 시작별 차이(평균 비용의 차이, episode별 상대 차이의 최댓값, 1e-6을 넘는 episode 수)를 보고한다.
   - 참고로 cloud CPU에서는 64 episode 7.79 s/batch(1498 결정/s), 256 episode 26.99 s/batch(1716 결정/s)였다.
3. 버전, 장치, 재현 판정, batch별 처리량을 사용자에게 보고한다.

**알아 둘 점.**
- GeForce GPU의 float64 처리량은 float32보다 크게 낮다. rollout은 작은 행렬의 긴 순차 scan(결정 220 × 제어 25 × RK4 4)이라 batch를 키울수록 이득이 난다. 실제 배수는 2의 측정으로 판단한다.
- float32 전환은 설계 변경으로 다룬다(승인 필요).
  - spec `sec:envcheck`에 따르면 float32 궤적은 float64와 관절 각 0.13 rad, 법선력 2.46 N(RMS) 이내로 일치했다.
  - tank margin 판정(−0.01 J 기준)과 보장 검사에 미치는 영향을 먼저 확인해야 한다.
- 손의 role loss는 긴 scan을 역전파하므로 메모리를 많이 쓴다(`jax.checkpoint` 사용 중). batch를 키울 때 VRAM 16 GB 한계를 확인한다.
- `l2_train.py`의 반복당 episode 수는 세 번째 위치 인자(`N_EP`)이고, 손의 minibatch는 `min(32, N_EP)`이다.

## 8. 다음 단계 (제안; 각 항목은 사용자 승인과 사전 등록 후)

spec `sec:l2status`의 제안을 따른다. 사용자는 학습률을 낮추거나 scheduling하는 것도 검토하라고 했다.

1. **평가 규칙:** 표본 gripper 평가를 병기하고, 판정용 평가의 episode 수를 늘린다.
2. **최적화 pilot** (반복 300 checkpoint에서 짧게):
   - 반복당 episode 수(예: 128, 1024, 4096).
   - KL에 맞춘 학습률(목표 0.01–0.02) 또는 고정 감쇠.
   - entropy 계수.
   - 손의 학습률 감쇠도 같은 틀에서 본다.
3. **손의 역할:** role loss에 옮김 항을 넣고, 오프라인으로 먼저 시험한다(`eval/diagnostics/l2_hand_fresh.py`의 틀). 통과 기준은 30 반복 동안 전이 잔차 < 1.768, role loss 증가 ≤ 10%다.
   $$\mathcal L_{\mathrm{tr}}=\mathbb E_{a,b}\|G(q_b)^\top(\bar a+z_a^\star)-u^\star_b\|^2,\quad z_a^\star=G(q_a)(G(q_a)^\top G(q_a)+\epsilon I)^{-1}(u^\star_a-G(q_a)^\top\bar a)$$
4. **잡기 관문과 장부:** 2의 결과를 본 뒤 정한다.
   - 잡기: 단계 1 비용에 속도 항을 넣거나, 물체 근처의 시작 상태를 쓴다.
   - 장부: 장부 하중을 공칭 기구학으로 손끝 하중으로 바꿔 관측에 넣는다.
5. **Attempt 4:** 통과한 항목만 묶어 수렴할 때까지 돌린다. 이후 분포 밖 평가, (사용자 지시가 있으면) seed 여러 개, ablation, 7-DOF(Stage C; 로봇 기술 파일은 `rsc/`).

## 9. 운영상의 함정

- **Warm start.** `l2_train.py`에 checkpoint를 주면 행동 모드(`act`)와 optimizer 상태를 그대로 이어받는다(`opt_reset=1`로 초기화). 시작 로그의 행동 모드가 맞는지 확인한다.
- **평가의 놓기.** 결정론적 평가의 단계 4 비용은 정책보다 나쁘게 나온다(§6). 같은 평가 규칙끼리만 비교한다.
- **전이 잔차는 한 평가에서 두 배까지 흔들린다.** 판정은 여러 평가의 평균으로 한다(세 번째 시도의 H1 규칙).
- **오프라인 손 실험**에서는 data를 만든 손과 학습 중인 손이 다르다(replay가 기록된 torque를 쓴다). 결론은 같은 data의 변형끼리 상대 비교로만 낸다.
- **메모리.** 2026-11-15에 제한 없이 돌린 병렬 rollout이 RAM 31 GB를 다 써서, kernel OOM killer가 편집기까지 종료시켰다. 메모리를 많이 쓸 수 있는 작업은 `sh script/safe_run.sh mem=<상한> ...`(systemd unit, 상한 초과 시 그 작업만 종료, swap 없음, GPU 사전 할당 없음)로 돌린다. 측정값은 `records/parallel_check.log`, `records/l2_train_timing_pc.json`.
- **긴 run.** `nohup`이나 `setsid`로 띄우고, `train.log`의 `EVAL it N:` 줄로 진행을 본다. `script/report_checkpoint.sh`는 그 줄을 기다렸다가 보고물(분해, 학습 곡선, GIF, 선택적으로 신호 검사)을 만든다.
- **figure 이름**은 `eval/figures/fig_<what>.py` → `docs/figures/<what>.png`(가이드라인 E8). GIF는 `anim_rollout.py`가 run 이름으로 `docs/figures/rollouts/`에 만든다.
- **기록이 우선.** 문서와 기록이 어긋나면 그 즉시 `records/verified_values.md`의 `## Divergence (open)`에 적고, 정합시킨 뒤 지운다. 전달 시점에는 비어 있어야 한다.
