# pairl: project instructions (read first)

- Read docs/20261115_handoff.md (the handoff document) in full before any work. Section 0 gives the first task (build this repo from the bundle zip, verify, port to GPU, report); sections 2-9 give the research goal and invariants, the user's rules, the system, the current state and the next steps.
- Writing and verification rules: docs/guidelines/Research_Principles_and_Guidelines.md. Sections 5, 5a, 5b and 6, rules K7, K7b and K8 of 5c, and the rendering, batch-edit and bundle rules of 7 apply; the rest of 5c applies only to slides; sections 1-4 belong to another project and do not apply.
- Reply in Korean (no 반말, polite -습니다 style), technical terms in English, no emoji, no Chinese characters, key point first, concise and causal.
- Code comments in concise English, no separator lines.
- Never change the design (cost, observation, action, network, loss, hyperparameters, start distribution, evaluation rule) or start a training run without the user's approval. Pre-register every experiment in records/<name>_plan.md with its sha256 prefix in records/<name>_plan.hash before running it. Never edit the plan files that came in the bundle; to a new plan, only append amendments and the outcome, adding a hash line each time.
- One seed only unless the user says otherwise ("앞으로 내 별도 지시 없이는 seed별 학습은 절대 하지마. 한 seed만 할 것. 시간 낭비임."). Small pilots are fine.
- Platform: new runs and diagnostics are produced on this PC; compare results only within one platform. Cloud records stay valid and are never overwritten by recomputation (records/verified_values.md, "## Platform reproduction").
- Report numbers exactly as in the records. Training reports include data plots and rollout GIFs; give interim reports during long runs.
- Workspace: never create anything under ~/MIT outside ~/MIT/pairl. Local-only material (bundle extract, baselines, Python base, scratch scripts, measurements, proposals) lives in ~/MIT/pairl/_local/ (git-ignored); temp files go to ~/MIT/pairl/_local/tmp/ instead of /tmp and are cleaned up after use.
- Pool cache: data/pools/l2_pool_E0_6144.json is the cloud-built pool and is never regenerated on this PC (a rebuild differs in its budget entries by platform rounding; records/verified_values.md, "## Platform reproduction"); l2_train.py refuses to overwrite it.
- Run groups: all runs of one plan and code state go in data/runs/<YYYYMMDDHHMMSS>/<run>/ with manifest.json, listed in data/runs/INDEX.md (handoff 1.10). Each group folder holds at its top level summary.png (learning curves of all runs), eval_<run>_it<NNNN>.png (decision evaluation of each final checkpoint), decision.png for pilots (arm minus control with bootstrap CI), <run>_start{0,2,3}_it<NNNN>.gif (rollouts, git-ignored, at most about 5 MB each) and summary.md (purpose, plan, status, key numbers, links); INDEX.md links each summary.md. They are made automatically when a run finishes (script/finish_run.sh). Smoke tests, timing and debugging runs never go into data/runs.
- Evaluation and reports (standing, 2026-11-16): every reported checkpoint gets the phase success metrics of eval/diagnostics/phase_success.py (P1 grasp, P2 carry, P3 press, P3' class, P4 release; alone from their own starts and chained from the first start; bootstrap 95% CIs; records/phase_success.json). Every report leads with the success table (rows P1, P2, P3, P3', P4 alone and the full chain; columns L1 reference, attempt 3 at 300, previous best, current; changes whose CI excludes 0 marked), then one guarantee line (violations, non-finite states, minimum tank margin), then the bottleneck and why, and only then costs and diagnostics. Group folders hold success_table.md, success_curve.png, funnel.png, representative, comparison and grid videos (MP4 with GIF previews) and a summary.md that leads with the success table; script/finish_run.sh makes them. Extra evaluation work runs on the CPU at low priority; the GPU only between arms.
- Code freeze (standing, 2026-11-16): while a run group is active, never edit a file in its code-state hash scope (script/l2_train.py, src/pairl/learn, src/pairl/stageb, src/pairl/paths.py, pyproject.toml); prepare changes in a separate file or after the group ends. All remaining runs use XLA_FLAGS=--xla_gpu_deterministic_ops=true; compare only within that setting.
- Run everything from the repo root (python script/..., python eval/...); paths come from src/pairl/paths.py, never from the working directory.
- Before reporting a change as done: python script/check_sync.py prints "sync findings: 0"; after a note change also bash script/build_docs.sh <name> with all gate counts 0; after a code change that is not meant to change the numerics also JAX_PLATFORMS=cpu python script/port_check.py ref=pc reports EXACT (all 192 episode costs bit-identical to records/port_check_pc_baseline.json).
- Git: commit or push only when the user explicitly asks in that message; never propose a commit or draft a commit message on your own. Never commit the bundle zip, checkpoints other than the three allowed in .gitignore, or GIFs.
- Do not invent citations; check novelty claims with a web search. Do not send the user's personal information to external services.
